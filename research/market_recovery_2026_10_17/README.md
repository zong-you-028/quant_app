# Render 行情重啟還原與更新接續修正

使用者確認問題發生在 Render 網頁版。原部署只有帳本持久化到 Neon；行情為容器內 SQLite，且映像內 seed 截至 10/2。另有單次 90 秒即停止、前方失敗項目餓死後方待辦、費半排在股票批次之後、跨月補段全抓完才保存，以及同日新目標被舊完成紀錄擋住的問題。

## 修正

- `core/market_cache_storage.py`：公開欄位白名單、逐資源壓縮、Neon row lock 合併、較新資料優先；不備份整個 DB 或帳本。
- `core/market_backfill.py`：由舊到新逐月提交並保存有效游標；中斷不丟棄已完成月份。
- `core/market_update_workflow.py`：先還原，再檢查費半／優先 006208，一次操作自動接續批次，有限重試及無進度停止。
- `core/daily_market_update.py`：按日期與資料目標去重、提交後雲端保存、保存失敗保留 dirty marker；費半純讀快取不算下載，排除未完成的美股交易日。
- `main.py`：整次更新共用進度、顯示自動續抓批數、區分已存本機與已確認雲端保存。

預設沿用 `JOURNAL_DATABASE_URL`，可另設 `MARKET_DATABASE_URL`。不更改 Render 方案、不增加付費磁碟；僅建立獨立公開行情表 `quant_market_cache_v1`。

## 驗證情境

使用假雲端及暫存 SQLite，實際執行 seed hydration、資料提交和新 Python 程序還原：新實例初始為 10/2，還原後為 10/15，行情／籌碼／SOX／完成紀錄均可接續，沒有再次抓來源。另覆蓋 151 標的多批次、失敗前排公平性、部分月份保存、雲端故障後只重試保存、來源封鎖與進度停止，以及成功／失敗畫面提示。

`verify_tests.py` 保存完整根目錄回歸結果，封鎖正式 DB 及外部 HTTP；`verify_identity.py` 只讀核對凍結來源及前瞻封存。測試不連真實 Neon，不取得或提交投資帳本紀錄。

發布範圍的 33 個根目錄測試檔共 **355 項通過**（原 283 項加本次 72 項）；正式 DB 存取與外部 HTTP 請求均為零。測試清單由 Git 暫存／追蹤檔案取得，排除其他尚未發布的模型研究。

`verify_public_seed.py` 將整份公開 seed 的 154 個標的及 SOX 經模擬雲端壓縮後還原至全新 SQLite，逐表筆數相符：411,299 筆價量、410,786 筆籌碼、154 筆名稱及 3,104 筆費半。壓縮後合計 9,256,896 bytes；包含目前 151 個更新標的以外的 3 個舊 seed 標的。正式 DB、外部下載及帳本存取均為零。

## 限制

第一次啟用仍須補齊且成功保存一次；無法還原先前已被 Render 丟棄、從未持久化的更新。來源限流或休市時不能捏造新行情，仍會明示未達目標。台股及美股更新目標尚未採完整交易所假日曆。雲端未成功保存的本機進度仍可能在實例重啟時遺失。

固定模型、費用、成交、股票池及原 50／150 前瞻來源未改動。既有模型研究與其他 chat 的 ATR 研究不屬於此修正。
