# 更新寫入資料庫與每日成功下載限制

新增 app 編排層 `core/daily_market_update.py`，啟動與手動更新均使用它。原始 data_pipeline、market_regime、模型與兩個前瞻實驗受指紋源碼／名單／種子完全不改；研究封存仍使用各自既有更新器。

行情／籌碼仍透過既有原子合併提交到 `config.DB_PATH`。app 新增 `meta` 的 `app_daily_update:stock:<symbol>` 今日成功紀錄，依台北日期，只有實際需要更新且資料庫已達目標的標的才記完成。單純查快取不消耗額度；force/手動更新不略過每日規則。失敗／過期／待續抓可續作，成功部分跳過。同一天較早更新後遇到晚間新目標時仍跳過，真實舊日期／stale 明示，次日再補。

跨程序以同一 SQLite `BEGIN IMMEDIATE` 交易取得短期 lease，阻止兩個畫面同時下載；正常釋放只移除自己的 lease，崩潰 lease 十分鐘後到期。UI 請求預算最多300秒（預設90秒），不清除前瞻實驗 lock。每日紀錄跟行情在同一資料庫，磁碟被重建後不能跨重建去重；部署必須保留資料庫才能持久保留。

SOX 用既有增量來源與時效容許規則，不改策略 gate；新 `market_index_prices(symbol,date,close)` 保存收盤並同步 CSV，日內再開啟直接讀資料庫，CSV 遺失可由資料庫還原。來源失敗或仍超過時效容許不記完成。所有畫面仍報實際資料日期，沒有把完成紀錄當作新行情。

`test_daily_market_update.py` 驗證真實隔離SQLite寫入、日內force去重、全新Python程序保留紀錄、僅失敗者續抓、隔天恢復、早晚新目標仍誠實stale、查快取不消耗今日下載、資料庫lease互斥、過期回應不記成功、費半保存／重建CSV／失敗續抓。測試行情是合成來源回應，不是假稱已下載10/07公開行情；未讀寫正式投資紀錄。
